Treellis training-free generation framework v2
更新日期：2026-10-21

目的与实现方案
让用户更稳定地完成创建与修改：正常请求一次生成，检查失败才修复；局部修改保留其余内容；失败和取消不覆盖当前场景。
本轮改动集中在提示模板、共享生成服务与生成交互。结构树、参数面板和渲染器保留。

工作流
1. 根据入口区分 create / edit / node。全局编辑携带当前场景；节点编辑携带选中子树、祖先、兄弟、相关部件和世界空间几何摘要。
2. 加载完整必需模板与最多两个相关语法示例。复杂装配生成简短部件/尺寸/布局计划；简单参数修改无需额外规划请求。
3. GPT-6.1 Sol 通过 Responses API strict JSON schema 输出统一 envelope。新建使用 replace；数值、颜色、名称等小改动优先使用 patch；无法确定意图时返回澄清信息。
4. 原子应用候选 patch，并检查 AML 类型、参数、变换、布尔操作、重复与资源预算。patch 不允许修改 UID、元数据或结构，节点 patch 的路径限定在选中子树。
   结构替换由宿主按同父层唯一名称与节点类型恢复旧 UID、附注和分段设置；重名、类型改变或跨父级移动时不猜测身份。
5. 独立 worker 使用真实 Three.js / three-csg-ts 构造几何，检查有限边界、空布尔结果、实例及顶点预算；可检查数量、轴向尺寸、相对尺寸和中心对齐。
6. 如果检查失败，将候选结果与具体错误反馈给模型，最多修复两次。首组有效的非空验收条件会保留，修复不得通过删除或放宽条件绕过检查。
7. 检查通过后才返回结果。前端再次核对场景和选择是否已变化，避免迟到响应覆盖新编辑。整个生成作为一次可撤销操作；历史记录保存实际生成场景、模型/档位、模板哈希、tokens、耗时、修复次数和检查结果。

用户体验
显示准备、生成、检查与修复状态；Stop、关闭或 Esc 中止请求。
失败保留提示词与场景；全局生成期间新写的下一条提示词不会被清空。
全局与节点生成统一模型 gpt-6.1-sol；Low / Medium / High / XHigh / Max 对应同名 reasoning.effort，默认 Medium。
沿用个人 Key 输入与 Save Key；本地开发测试 Key 由后端从项目外读取。配置和发布移除方式见 README-Treellis.txt。

预算
最多 512 个树节点、2048 个展开实例、32 层深度、单个 repeat count 上限 64。
几何检查最多 500000 个累计生成顶点；worker 单次检查预算 15 秒。模型请求无总时长和响应读取空闲时长上限；服务最多并发两个生成任务，单次模式每任务最多三次模型调用。
输出预算（含推理）：Low 16000 / Medium 32000 / High 64000 / XHigh 96000 / Max 128000 tokens。
取消后停止等待和应用结果；上游已消耗的计算仍可能计费。

本轮验收
npm test：64 项通过；覆盖严格结构、补丁原子性与范围、结构添加/换序的身份与元数据保留、真实几何、重复/布尔、空间上下文、修复上限、不放宽条件、取消、API 错误与流解析。
真实 API 四例：四腿桌子创建 14.1 秒；全局单尺寸修改 4.4 秒；依据兄弟宽度的节点修改 5.1 秒；圆周六体重复 8.5 秒。四例均通过独立断言、零修复，总计 14480 tokens。不同场景、网络及档位的耗时会变化。
追加结构修改验收：添加 Badge 部件 18.1 秒、4161 tokens、零修复；原有两个节点的全部字段、UID、附注和球体分段设置严格保留。五项验收合计 5/5 通过、50.3 秒、18641 tokens；此合计不含其他诊断及浏览器调用。
浏览器实际验证：创建 cube、节点仅改宽度、精确撤销/重做、生成快照、保留下一条输入、Stop、节点 Esc，以及 Viewport/输入区交界线拖动。
界面首个请求曾出现一次 NETWORK_ERROR；手动重试与后续代表用例成功。网络错误会保留输入，不自动重复计费请求。

证据与限制
这是一个已实现并通过代表用例的改进版本，不能据此声称推理框架最优或整体质量提升已有统计证明。
客观检查项由模型提出，可能遗漏用户要求；几何通过不保证语义或视觉正确。AABB 是轴对齐边界；count 是展开的输入 primitive 数量，不是布尔后的连通组件数，也不自动等同语义部件数。
本轮未加入多视角截图的视觉评价、多候选排序、任意 CAD 约束求解或训练。下一步应在同模型、同 tokens/调用预算下比较旧流程、新流程及去掉空间上下文/几何反馈的消融版本，统计任务成功率、非目标修改、延迟与费用，再决定是否加入按需视觉复核。
