Treellis 实时进度与分步生成方案
2026-10-21

问题定位
截图中的 The model took too long 来自原程序的 150 秒 API 计时。输出截断是另一类错误，会返回 incomplete/max_output_tokens。二者分别处理，不能仅提高 tokens 解决计时问题。

已实现的流程
单次模式：准备上下文 -> GPT 生成 -> AML/真实几何/客观条件检查 -> 必要时修复 -> 应用完整结果。
分步模式：规划独立部件 -> 生成当前子树 -> 检查完整场景 -> 应用该步骤 -> 处理下一部件 -> 完成。
新建模式先生成最多18个源 primitive 的粗略骨架，然后规划其主要子树。每轮规划最多6个不重叠目标；无效计划最多纠正一次，每个部件最多修复一次。
所有请求保持 gpt-6.1-sol 及用户所选 effort，包括规划。XHigh/Max 提供 Step by step 与 Single pass，默认分步；较低档位使用单次模式。
顺序执行便于后续部件使用前面已经更新的场景上下文。本轮没有加入并行修改；并行生成需要先明确跨部件尺寸、连接点与合并冲突的处理规则。

用户看到的进度
显示真实任务阶段、当前部件 x/y、已完成部件列表，以及累计用时 MM:SS。
分步任务单独显示 Completed X/Y tasks；X只统计已检查并应用的任务，不把“正在执行第几项”计为已完成。计划确定后列出全部任务名称，标注 Completed / In progress / Pending；Stop或错误后保留清单，当前未完成项显示 Paused / Needs attention。
规划完成前总数待确定；新建骨架完成后还会规划细化任务，不将暂时的1/1误报为整轮完成。计数、累计用时和当前任务固定在可滚动清单顶部。
全局进度现在位于输入框与3D视图区交界处的小悬浮条，默认仅显示简短进度及用时。悬停或键盘聚焦展开任务清单、摘要与Continue按钮；点击可固定展开，Escape、关闭按钮或点击外部可收起。详情使用浮层，不占输入框下方高度，也不阻挡两侧分隔线拖动。节点弹窗仍使用内联进度。
模型输出经 SSE 实时接收；可用时展示 OpenAI 的公开 reasoning summary，生成 AML 时只显示收到的字符数。原始 AML JSON 及未公开推理不作为进度文本展示。
阶段信息来自实际执行事件，不伪造百分比或“已经细化某部件”的消息。模型尚未输出摘要时，显示正在处理请求以及持续计时。
已用时间包含模型生成和本地检查；继续任务时累计之前的活跃时间，停止间隔不计入。

时长与输出预算
取消原150秒总计时；模型请求不设置总时长、响应头等待或响应体空闲时长上限，直到完成、出现真实网络/API错误或用户点Stop。
仅新建网络连接保留20秒连接计时，用于识别无法连通OpenAI；它不限制已连接模型的思考时长。几何worker仍有15秒本地计算资源预算。
输出token上限包含推理和最终结果：Low16000、Medium32000、High64000、XHigh96000、Max128000。上限是允许的容量，不会强制用满。
单纯提高输出上限不保证更快或更好；分步减少每次必须输出的整棵树大小。

中断、续跑与编辑保护
每个子树经结构/预算/几何检查后才作为checkpoint返回；前端再检查场景版本和当前选择，才更新视图。
每一步各自记录可撤销快照，最终确认不会再重复应用同一结果。节点弹窗仅在整个任务完成后关闭。
Stop会中止当前请求，已完成步骤保留。网络断开或后续步骤失败时，当前页面可Continue remaining，使用保留的计划和现有场景继续。
续跑计划绑定完整场景哈希、原提示词、档位与选择范围；改变这些条件后禁用旧计划。计划仅存在当前页面内；刷新前需保存场景，刷新后可从保存的场景重新发起任务。
未完成的JSON和断流结果不会作为完成结果应用。此轮尚未实现跨页面持久化的后台作业服务。

质量边界
每步只修改所选子树，其他节点由宿主保留；全场景仍受512节点、2048展开实例等预算约束。
安装位置、整体比例和共享约束会传入每一步提示；目前没有通用接口/碰撞约束求解器，不能据此保证所有语义或视觉要求正确。
规划、摘要和验收条件可能遗漏要求。需要基于真实任务对比成功率、耗时、费用和非目标修改，不能把本次实现称为最优推理框架。

conversation只接收最近六条user/assistant消息，每条最多4000字、合计12000字。原问题和正式答复参与下一次推理；公开进度摘要不作为对话历史。单次和分步生成均传递历史，续跑计划也绑定对话版本。
